# 运行说明

本文说明如何在干净环境中安装依赖、配置、初始化数据、调用上下文模块并运行测试。所有命令都在仓库的
`minimax/` 目录下执行。凭据只通过环境变量提供，仓库中只有占位值（`.env.example`）。

## 1. 环境要求

| 项目 | 要求 | 本仓库实测 |
| --- | --- | --- |
| 操作系统 | Linux x86_64 / aarch64；macOS（Apple Silicon）理论可用 | Ubuntu 24.04 x86_64 |
| Python | 3.11 或 3.12（PowerContext 1.4.1 要求 ≥ 3.11） | 3.12.3、3.11（见第 8 节） |
| 安装工具 | 推荐 [uv](https://docs.astral.sh/uv/)（会自动下载 Python 3.12）；没有 uv 时用 `python3 -m venv` + pip | uv 0.13.6 |
| 其他命令 | bash、git（用于在测试日志中记录代码版本，缺失时记为 `unknown`） | |
| 网络 | 安装时需访问 PyPI；默认验收流程（回放）不访问任何模型服务 | |
| 磁盘 / 内存 | 约 1.1 GB 磁盘（`.venv` 约 480 MB，嵌入式 seekdb 数据约 570 MB）；内存 1 GB 以内 | |
| 端口 | 本机 `127.0.0.1:17439`（PowerContext Server，可用 `SDD_PC_PORT` 修改） | |

不需要 Docker、不需要外部数据库、不需要模型 API Key 即可跑通全部验收。

## 2. 依赖版本与接入方式

| 技术 | 版本 | 实际接入方式 | 作用 |
| --- | --- | --- | --- |
| seekdb | `pylibseekdb==1.4.0.post2`（引擎 `5.7.25-OceanBase seekdb-v1.4.0.0`） | 嵌入式实例（`pylibseekdb.open`），通过其 unix socket 用 `PyMySQL==1.2.0` 执行带参数的 SQL；全文索引使用 `ik` 分词器 | 存储规格条目、代码符号、测试用例、文件正文、关联与修订历史；上下文的每一项都来自 SQL 查询结果 |
| PowerContext | `powercontext[cli,server]==1.4.1` | 本地 Server（`powercontext server run`，SQLite 存储，无需模型）；模块通过官方异步 Python Client `powercontext.client.PowerContextClient`（HTTP API）读写 | 保存任务进展与验证结果（Scope、Memory、Source、Work Contract、Handoff、Task Outcome），重启后读回并用于后续上下文和任务处理 |
| MiniMax | 官方 OpenAI 兼容接口 `POST {MINIMAX_BASE_URL}/chat/completions`（默认模型 `MiniMax-M3`，`httpx==0.28.1`）；或 MiniMax 官方 Hugging Face Space `MiniMaxAI/MiniMax-Text-01`（`gradio_client==2.7.2`） | 生成代码修改；每轮修改后运行目标与回归测试，失败信息作为下一轮输入 |
| 测试 | `pytest==9.2.0` | 子进程运行，JUnit XML 解析结果 | 修改前后验证 |

完整的锁定依赖见 `requirements.txt`（由 `requirements.in` 通过 `uv pip compile --universal` 生成）；
`requirements-hf.txt` 仅在使用 Hugging Face Space 通道时需要。

## 3. 安装

```bash
cd minimax
bash scripts/install.sh            # 创建 .venv 并安装 requirements.txt
# 可选：同时安装 hf-space 通道所需的 gradio_client
SDD_WITH_HF=1 bash scripts/install.sh
```

`install.sh` 优先使用 uv（`uv venv --python 3.12` + `uv pip install -r requirements.txt`）；没有 uv 时使用
`python3.12`/`python3.11` 的 `venv` 与 pip。Debian/Ubuntu 上若提示 `python -m venv` 不可用，请安装 uv
（`curl -LsSf https://astral.sh/uv/install.sh | sh`）或系统包 `python3-venv`。安装结束会打印各依赖的实际版本。

手动安装等价于：

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
```

## 4. 配置

默认配置即可运行，无需任何凭据。需要调整时复制 `.env.example` 为 `.env`（已被 git 忽略）或直接导出环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MINIMAX_API_KEY` | 空 | MiniMax 官方 API Key；仅 `--mode live` 需要。**只放在环境变量或 `.env` 中，不要提交** |
| `MINIMAX_BASE_URL` | `https://api.minimaxi.com/v1` | 国际站使用 `https://api.minimax.io/v1` |
| `MINIMAX_MODEL` | `MiniMax-M3` | 也可用 `MiniMax-M3.1-Flash`、`MiniMax-M2.7` 等 |
| `MINIMAX_MAX_TOKENS` / `MINIMAX_TIMEOUT` | `32768` / `600` | live 模式的生成上限与超时（秒） |
| `MINIMAX_HF_SPACE` | `MiniMaxAI/MiniMax-Text-01` | hf-space 模式使用的 Space |
| `SDD_PC_PORT` | `17439` | 本地 PowerContext Server 端口 |
| `SDD_RUNTIME_DIR` | `./.runtime` | 运行时目录：seekdb 数据、PowerContext 数据、样例工程工作副本 |
| `SDD_SEEKDB_HOST` 等 | 空 | 设置后改为连接 seekdb / OceanBase 服务器（MySQL 协议，见第 9 节） |

## 5. 一键验收（推荐）

```bash
bash scripts/demo_accept.sh
```

脚本从空状态开始依次执行 24 个步骤（重置 → 初始化 → 导入 → 生成上下文 → 修改前测试 → 写入状态 → MiniMax 修改 →
修改后测试 → 写入状态 → 停止并重启 PowerContext → 新进程读回状态并生成上下文 → 规格更新为 v2 并重新导入 →
生成新上下文 → 自动核对六项验收），约 70 秒。每一步的命令与退出码写入 `evidence/demo_steps.tsv`，完整输出写入
`evidence/demo_accept.log`。结尾应看到：

```text
六项验收：
  1. 能够运行         PASS
  2. MiniMax 实际参与 PASS
  3. 上下文正确        PASS
  4. 数据库实际参与      PASS
  5. 状态能够复用       PASS
  6. 代码修改有效       PASS

总体：PASS（六项全部通过）；明细见 evidence/验收结果.md
```

`SDD_EDIT_MODE` 选择 MiniMax 步骤的执行方式：

| 取值 | 行为 | 需要 |
| --- | --- | --- |
| `replay`（默认） | 回放录制的真实 MiniMax 会话 `evidence/minimax/session_recorded.json`：重新生成提示词并与录制时逐字节比较，依次应用每轮回复、重跑测试，核对每轮 diff | 无 |
| `live` | 调用 MiniMax 官方 API，实时生成修改；新会话写入 `evidence/minimax/sessions/` | `MINIMAX_API_KEY` |
| `hf-space` | 调用 MiniMax 官方 Hugging Face Space（无需 Key，依赖该 Space 在线） | `SDD_WITH_HF=1` 安装 |

例如：`MINIMAX_API_KEY=<你的 Key> SDD_EDIT_MODE=live bash scripts/demo_accept.sh`。live 模式下模型输出不保证
与录制完全相同（题面不要求重新生成相同补丁），验收会按本次会话核对 diff 与测试。

## 6. 调用入口：`./sdd` 命令

`./sdd` 等价于 `.venv/bin/python -m sdd_context`，所有命令向标准输出打印 JSON；全局参数 `--task <file>` 指定任务
（默认 `sample_task/task.toml`），`--save <file>` 把输出 JSON 另存一份。

| 命令 | 输入 | 输出 / 副作用 |
| --- | --- | --- |
| `init` | 样例工程 `sample_app/` | 复制工作副本到 `.runtime/workspace/sample_app`；创建 seekdb 库表；生成 Server 配置并启动 PowerContext Server；打印各组件版本 |
| `ingest` | 工作副本中的 `specs/*.md`、`taskboard/**/*.py`、`tests/test_*.py` | 写入 seekdb（文档、规格条目、代码符号、测试用例、关联、修订历史）；打印导入批次与新增/修改/删除的规格条目 |
| `context [--out f.json] [--md f.md] [--full]` | 任务定义 + seekdb + PowerContext | 开发上下文：适用规格条目（变更/保持，含来源 `path#Lx-Ly`、sha256、revision）、待修改文件与符号、目标与回归测试、已完成/待办/已有验证结果、产生每一项的 seekdb 查询编号；SQL 写入 `evidence/seekdb_queries.log` |
| `test --suite target\|regression\|full --label before\|after [--expect fail\|pass]` | 上下文选出的测试 | 运行 pytest，日志含命令、退出码、git commit、代码摘要，写入 `evidence/tests/`；`--expect fail` 要求所有用例都因断言失败（排除收集错误、导入错误等环境问题） |
| `save-state --phase baseline\|verified` | 测试结果、MiniMax 修改记录 | 写入 PowerContext：Memory、验证记录 Source、Work Contract、Handoff（预览后提交）、Task Outcome；记录写入 `evidence/state/` |
| `edit [--mode auto\|live\|hf-space\|replay] [--record] [--force] [--max-attempts N]` | 上下文 + PowerContext 状态 | MiniMax 修改工作副本中的代码，写出 `evidence/code.diff`、`snapshots/before|after/`、会话记录；若 PowerContext 显示任务已完成且规格、代码未变则跳过 |
| `resume [--out f.json]` | PowerContext | 读回 Handoff、验证记录、MiniMax 修改记录、Memory，给出下一步 |
| `server start\|stop\|restart\|status` | — | 管理本地 PowerContext Server（pid、存活状态） |
| `spec-update --version v2` / `spec-update --restore` | `sample_task/spec_updates/v2/` | 用更新后的规格覆盖工作副本的 `specs/`（之后需重新 `ingest`）/ 恢复 v1 |
| `accept` | 本次运行的 `evidence/` | 核对六项验收，写出 `evidence/验收结果.md`、`evidence/acceptance_report.json` |
| `devlog` | `evidence/minimax/session_recorded.json` | 重新生成 `evidence/minimax/开发记录.md` |
| `reset` | — | 停止 Server，删除 `.runtime/` |

## 7. 分步运行

```bash
./sdd reset && ./sdd init                      # 空状态
./sdd resume                                   # status: empty
./sdd ingest                                   # 导入 v1 规格、代码、测试
./sdd context --out evidence/context_v1.json --md evidence/context_v1.md
./sdd test --suite target --label before --expect fail
./sdd test --suite regression --label before --expect pass
./sdd save-state --phase baseline
./sdd edit                                     # 无 Key 时回放，有 MINIMAX_API_KEY 时调用 live
./sdd test --suite target --label after --expect pass
./sdd test --suite regression --label after --expect pass
./sdd test --suite full --label after --expect pass
./sdd save-state --phase verified
./sdd server stop && ./sdd server start        # 重启 PowerContext
./sdd resume                                   # 新进程读回：status: restored，handoff@2
./sdd context                                  # done 含 edit/verify，todo 为空
./sdd edit                                     # skipped: true（状态显示已完成）
./sdd spec-update --version v2 && ./sdd ingest
./sdd context --out evidence/context_v2.json   # TAG-001 rev 2、新增 TAG-005、todo 提示重新实现
./sdd accept
```

## 8. 测试命令

| 目的 | 命令 |
| --- | --- |
| 样例工程（修改前，仓库中的版本） | `cd sample_app && ../.venv/bin/python -m pytest -q`：10 个目标用例失败、17 个通过 |
| 样例工程（修改后，工作副本） | `cd .runtime/workspace/sample_app && ../../../.venv/bin/python -m pytest -q`：27 个全部通过 |
| 按上下文选择的目标/回归/全量测试 | `./sdd test --suite target|regression|full --label before|after` |
| 上下文模块自身的测试 | `.venv/bin/python -m pytest -q`（`module_tests/`，含一个使用临时嵌入式 seekdb 的集成测试） |

也可以直接对快照验证：把 `snapshots/after/taskboard/service.py` 复制进样例工程的副本再运行 pytest。

在 Python 3.11 上验证：`SDD_PYTHON_VERSION=3.11 bash scripts/install.sh && bash scripts/demo_accept.sh`。

## 9. 使用 seekdb / OceanBase 服务器（可选）

默认使用嵌入式 seekdb，无需任何服务。若希望使用已有的 seekdb 服务器或 OceanBase（MySQL 模式）：

```bash
export SDD_SEEKDB_HOST=127.0.0.1 SDD_SEEKDB_PORT=2881 SDD_SEEKDB_USER=root SDD_SEEKDB_PASSWORD=<占位>
export SDD_SEEKDB_DATABASE=sdd_context
bash scripts/demo_accept.sh
```

SQL 完全相同（包括 `FULLTEXT INDEX ... WITH PARSER ik` 与 `MATCH ... AGAINST`），要求服务器版本支持 ik 全文分词器。
本仓库的验收结果使用嵌入式 seekdb 产生，服务器模式未在本环境实测。

## 10. 输出位置

| 路径 | 内容 |
| --- | --- |
| `evidence/context_v1.json/.md`、`context_baseline.json`、`context_resume.json/.md`、`context_v2.json/.md` | 各阶段的上下文输出 |
| `evidence/seekdb_queries.log` | 每次查询的 SQL（已代入参数）、行数和返回行 |
| `evidence/tests/*.log/*.json` | 修改前后测试日志（命令、退出码、git commit、代码与测试摘要） |
| `evidence/state/*.json` | PowerContext 写入、Server 停止/启动的 pid、重启后读回的状态、重启后 edit 被跳过 |
| `evidence/minimax/` | 录制会话、开发记录、回放核对、早期试验记录 |
| `evidence/code.diff`、`snapshots/before|after/` | 代码差异与修改前后快照 |
| `evidence/验收结果.md`、`acceptance_report.json`、`demo_steps.tsv`、`demo_accept.log` | 六项验收结果与运行日志 |
| `.runtime/` | 运行时数据（seekdb、PowerContext SQLite、Server 日志、样例工程工作副本），`reset` 删除 |

每次运行 `demo_accept.sh` 会覆盖 `evidence/` 下的运行产物（录制的 MiniMax 会话与开发记录不会被覆盖）；
`bash scripts/reset.sh --evidence` 可把 `evidence/`、`snapshots/` 恢复为仓库提交的版本。

## 11. 重置

```bash
bash scripts/reset.sh             # 停止 PowerContext Server，删除 .runtime（seekdb、PowerContext 数据、工作副本）
bash scripts/reset.sh --evidence  # 另外把 evidence/、snapshots/ 恢复为提交版本
```

仓库中的 `sample_app/` 始终保持修改前状态，所有修改都发生在 `.runtime/workspace/sample_app`。

## 12. 已知限制

- 只在 Linux x86_64（Ubuntu 24.04，Python 3.11/3.12）上实测；Windows 不支持（脚本为 bash，Server 管理使用 POSIX 进程组）。
- 规格解析约定：Markdown 条目标题为 `## <编号> <标题>`，条目元数据 `- 类型: 变更|保持`、`- 关键词:`；代码与测试解析只支持 Python。
- 组件选择依赖全文检索得分（变更条目得分 ≥ 最高分 × 0.3）；规格写法差异很大时可能需要调整阈值。
- live / hf-space 模式的输出由模型决定，不保证与录制一致；`edit` 最多与 MiniMax 往返 3 轮，仍未通过测试时把工作副本恢复为修改前代码、返回非零退出码并保留全部会话记录。实测 hf-space（MiniMax-Text-01）用同一提示词：一次首轮通过、一次经测试反馈第 2 轮通过、一次（反馈改进前）3 轮未通过，详见 `evidence/minimax/sessions/README.md`。
- hf-space 通道依赖 MiniMax 官方 Space 在线，且 Space 的 `/chat` 只接收单条消息（多轮内容会拼接发送）；Space 背后的具体模型版本由 Space 配置决定。
- seekdb 服务器 / OceanBase 模式未在本环境实测；嵌入式 seekdb 首次打开约 2–3 秒。
- 端口 17439 被占用时 `init` 会报错，请设置 `SDD_PC_PORT`。
