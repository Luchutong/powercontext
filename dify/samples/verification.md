# 完整体验与重复验证

前置：按 README 启动服务，选择并导入主应用或基础验证版，绑定服务 URL/Secret。主应用需配置模型，默认 `ai`；独立基础验证版不调用模型，可以复现确定的规则和记忆。两份独立导入，无先后依赖；基础验证不能替代真实模型叙事验收。

## 样例一：一次善意会留到下次见面

初始状态：每次重复验证使用新的随机人生口令，例如 `judge-moon-20261030-01`；该口令未在本服务使用过。新档为月币 80、人缘 0、荒诞度 0、选择次数 0、档案 v1。

| 步骤 | 输入 / 操作 | 应观察到的表现 |
| --- | --- | --- |
| 1 | 新建 Dify 会话，填入口令，发送「开始」 | 第一天「船票比人生贵」，出现三个行动，数值 80/0/0，档案 v1 |
| 2 | 发送 `A` | 船票让给小锈，进入第二天，月币 65、人缘 3、荒诞度 0；真实保存后显示 v2 |
| 3 | 在 Dify 新建另一个会话，填写相同口令，发送「继续」 | 仍然是第二天，数值和选择不丢失；小锈记得玩家让出了船票；不重扣 15 月币 |
| 4 | 发送「档案」 | 显示第一天的真实选择和结果；不产生新的游戏选择 |
| 5 | 新建会话，填写另一个全新口令，发送「开始」 | 独立新档 80/0/0；不会出现前一口令的选择 |

在 AI 模式下，措辞允许变化，选择、数值、日数、关系事实和选项必须符合表格。实际结果与证据路径见 `../evidence/README.md`。

## 样例二：完整结局与旧人生

使用新的口令，从「开始」后连续发送六次 `A`。应依次经过六个决策场景，最终进入「银河合伙人」。预期最终数值：月币 40、人缘 12、荒诞度 0；档案 v7。

输入「档案」应列出六次真实选择及结局。输入「新人生」后回到 80/0/0、第一天，人生编号变为 2，旧人生摘要仍显示银河合伙人；PowerContext 创建新的正文版本而不是抹去旧版本。

另一个新口令，先做任意五次选择，第六次选 `B`：应进入「地球归来者」。第六次选 `C`：应进入「月球传说」。

## 异常与重置

- 输入不存在的行动如 `D`：提示合法操作，日数和余额不变。
- 服务不可用或写入冲突：不显示本回合已保存，按提示先发送「继续」读回。
- 对 API 同一票据重复提交：不重复增加版本、不重复扣款；集成测试有对应实际检查。
- 重复样例时优先使用新随机口令，获得完整干净初始状态。游戏内「新人生」会保留旧人生摘要，不等同于删除一切历史。
- 如需完全隔离的一轮服务验收，在 `run_powercontext.py --data <新的专用空目录>` 启动独立实例，并为该轮配置专用配套服务。不要清理其他项目的数据或 Docker 卷。
