# 数据库课程笔记：索引结构

> 示例资料，内容为个人学习笔记。

## B+ 树
B+ 树把所有数据放在叶子节点，叶子之间用链表相连，适合范围查询。读性能稳定，但随机写入会引起页分裂，写放大明显。传统关系型数据库（如 MySQL InnoDB）的主键索引就是 B+ 树。

## LSM 树
LSM 树（Log-Structured Merge Tree）先把写入放进内存表，满了再顺序刷到磁盘，后台再做合并（compaction）。写入吞吐高，适合写多读少的场景；代价是读时可能要查多层，需要布隆过滤器加速。OceanBase、RocksDB 都采用了 LSM 树的思路。

## 向量索引
HNSW 是常用的近似最近邻图索引，召回率高、查询快，但内存占用较大；IVF 先聚类再在少数簇里搜索，内存更省。
